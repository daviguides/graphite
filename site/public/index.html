How it works

Extract, persist, serve

One daemon per repo keeps the graph always hot. Every agent session queries the same indexed graph through a local socket.

01

Extract

Tree-sitter parses source code into symbols, calls, imports, inheritance. Python today; Rust and TypeScript next. Deterministic IDs, edge confidence tags.

02

Persist

CozoDB (embedded Datalog) holds facts and derives confidence by rule. In-memory adjacency serves traversals in microseconds. Atomic per-file updates; reads never wait for writes.

03

Serve

CLI, MCP shim, and interception hooks deliver blast radius, source inline, covering tests. The agent gets the answer and the code in one call.

Honesty built in

The agent knows when to trust the graph

Every edge carries a confidence tier and provenance. Responses disclose when a result is a lower bound and why. Assertiveness from transparency, not from hiding uncertainty.

EXTRACTED

Parsed directly from source. Static call, explicit import, type annotation. The graph saw it in the AST.

INFERRED

Derived by rule. Duck-typed call resolved to a likely target. Marked with provenance so the agent can verify if needed.

AMBIGUOUS

Multiple possible targets. Dynamic dispatch, reflection, generated code. The graph says "I don't know which one" instead of guessing.

Under the hood

Hybrid engine, measured

Always-hot graph

File watcher indexes eagerly. Queries hit an already-indexed graph. At most a short freshness barrier, never a rebuild.

mtime check + BLAKE3 per file

Microsecond traversals

In-memory adjacency serves blast radius in plain Rust BFS. CozoDB handles facts, rules, and search.

19-80 µs on worst real hub

Source inline

Responses return verbatim source with line numbers alongside graph context. One call = dependency context + actual code.

Zero follow-up file reads

Single binary

Tree-sitter grammars, CozoDB, daemon, clients, file watcher. One Rust executable. No runtime, no npm, no venv.
